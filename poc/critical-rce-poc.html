CRITICAL

Unauthenticated Python execution

VulnAPI-101 1.0.0 accepts Python source in a public HTTP request, passes it to exec(), and returns the value produced inside the server process.

1. Entry pointPOST /api/debug/execute
2. Missing controlNo authentication or authorization check
3. Security impactPython runs with the Flask process's privileges

The decisive source

app/routes/debug.py reads the attacker-controlled code field and passes it directly to exec(). app/__init__.py registers the debug blueprint for every application instance.

data = request.get_json()
code = data.get('code')

local_vars = {}
exec(code, {'__builtins__': __builtins__}, local_vars)

Safe demonstration boundary

The supplied checker accepts only localhost and loopback IP addresses. Its payload performs the calculation 7 × 6 and returns a fixed marker. It does not invoke a shell, access files, collect secrets, persist data, or change application state.

Run the proof of concept

  1. From the repository root, start the training app on loopback only:
flask --app run:app run --host 127.0.0.1 --port 5000 --no-debugger --no-reload
  1. In a second terminal, run the checker:
python poc/critical-rce-poc.py

Observed local verification

Target: http://127.0.0.1:5000/api/debug/execute
Authentication: none
Payload: result = 'VULNAPI_RCE_CONFIRMED:' + str(7 * 6)
HTTP status: 200
Returned result: VULNAPI_RCE_CONFIRMED:42
PASS: unauthenticated server-side Python execution confirmed.

This output was recorded from VulnAPI-101 1.0.0 running on 127.0.0.1. The marker can only appear in this response if the server evaluates the supplied Python statement and returns its result variable.

Remediation

Remove the execution endpoints and do not register the debug blueprint outside an isolated training environment. Authentication alone is not an adequate control for arbitrary code execution. Add a regression test that verifies /api/debug/execute and /api/debug/eval are absent from deployable builds.
